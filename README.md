# تطبيق الشرطة البلدية (Municipal Police Field App) 🇹🇳

تطبيق ويب ميداني متكامل باللغة العربية وموجه للهواتف الذكية بنظام RTL، مصمم خصيصاً لأعوان وإطارات الشرطة البلدية بالجمهورية التونسية لمعاينة وتسجيل المخالفات في الميدان بدقة وسرعة وبدون الحاجة لإنترنت دائم (Offline-Capable).

---

## 🏛️ الهوية البصرية والمواصفات المؤسساتية

- **النمط المؤسساتي الرسمي**: مظهر قانوني ورسمي رصين يعكس هيبة الدولة والجماعات المحلية (وليس مظهر شركات ناشئة).
- **اللون الأساسي المهيمن (Primary)**: أزرق بحري داكن عميق `#0b2545`.
- **لون التأكيد والنجاح (Success)**: أخضر بلدي `#1f9d55`.
- **لون الإنذار والتنبيه (Destructive)**: أحمر أمني `#d62828`.
- **الخط الطباعي المعتمد**: خط "Cairo" العربي الرسمي من Google Fonts بجميع أوزانه.
- **التصميم الميداني**: أزرار لمس كبيرة (أكبر من 48px) مهيأة للاستخدام الميداني بيد واحدة تحت أشعة الشمس.
- **جاهزية PWA**: ملف `manifest.json` وأيقونات مؤسساتية للتثبيت المباشر على هواتف Android كـ App مستقل.

## 👥 المستخدمون والرتب (حسابات تجريبية مهيأة مسبقاً)

| اسم المستخدم | كلمة المرور | الرتبة | الصلاحيات الميدانية والإدارية |
|---|---|---|---|
| `agent` | `agent` | **عون** | تسجيل المخالفات، التقاط الصور والـ GPS، البحث، واستعراض السجلات |

## 📱 الشاشات الـ 11 المنجزة والوظائف الميدانية

1. **شاشة الدخول (`/login`)**:
   - نموذج تسجيل الدخول مع الشعار الرسمي للشرطة البلدية.
   - أزرار تعبئة سريعة للحسابات التجريبية الثلاثة (عون، رئيس فرقة، رئيس مركز).
2. **شاشة الاستقبال ومنصة الانطلاق (`/`)**:
   - بطاقة العون المتصل مع رتبته وتوقيت حي بالثواني وبتاريخ تونسي كامل (`ar-TN`).
   - بطاقات إحصائيات فورية (المخالفات، المخالفون المتكررون، عمليات الحجز).
   - شبكة أزرار لمسية كبيرة وسريعة لكافة الأقسام.
3. **البحث السريع الميداني (`/search`)**:
   - بحث فوري لحظي أثناء الكتابة حسب: الاسم، اللقب، رقم بطاقة التعريف الوطنية (CIN)، رقم لوحة السيارة، أو رقم مرجع المخالفة.
   - شارة حمراء بارزة **"مخالف متكرر"** لمن لديه 3 مخالفات فأكثر.
4. **تسجيل مخالفة جديدة (`/violations/new`)**:
   - **المخالف**: بحث آلي فوري برقم ب.ت.و لاسترجاع بياناته تلقائياً أو إنشاء ملف جديد مع إمكانية التقاط صورته.
   - **المكان**: تحديد الولاية، المعتمدية، الحي، والشارع + زر **التقاط GPS فوري** مع جلب العنوان التلقائي (Reverse Geocoding عبر OpenStreetMap Nominatim)، ومعاينة مباشرة على خرائط Google.
   - **تفاصيل المخالفة**: صنف المخالفة، نوع النشاط، نوع البضاعة، الوصف الميداني، الإجراء المتخذ، والملاحظات.
   - **وسيلة النقل**: تفعيل وسيلة النقل مع نوعها، رقم اللوحة المنجمية، ولونها.
   - **الصور (5 أصناف ميدانية)**: كاميرا فورية (`capture="environment"`) أو المعرض:
     1. صور المخالفة
     2. صور البضاعة
     3. صور السيارة
     4. صور الوثائق
     5. صور مكان الانتصاب
   - **الحجز الفعلي**: تفعيل الحجز مع تحديد نوع المحجوز، الكمية، الوحدة (كغ، لتر، قطعة، صندوق، كيس، أخرى)، مكان الإيداع والمستودع البلدي.
   - **التوليد الآلي للمراجع**:
     - المرجع الفني: مثل `2026-SIDI-0001`
     - المرجع اللفظي التونسي بالأحرف العربية الكاملة (تفقيط): مثل *"ألفان وستة وعشرون - سيدي بوعلي - واحد"*.
5. **قائمة المخالفين (`/violators`)**:
   - بطاقات كافة المخالفين مع تصفية المخالفين المتكررين وإحصائيات التنبيهات والحجوزات.
6. **ملف المخالف الشخصي (`/violators/:id`)**:
   - كشف حساب المخالف، إجمالي المخالفات، آخر مكان ارتكبت فيه المخالفة، وسجل زمني تنازلي لكافة مخالفاته.
   - زر سريع لتحرير مخالفة جديدة لنفس المخالف.
7. **سجل المخالفات الميدانية (`/violations`)**:
   - استعراض شامل للمحاضر مع تصفية متقدمة حسب صنف المخالفة، الإجراء المتخذ، التاريخ، أو البحث النصي.
8. **تفاصيل محضر المخالفة (`/violations/:id`)**:
   - استعراض شامل لكافة البيانات، خريطة OpenStreetMap تفاعلية مدمجة + زر خرائط Google.
   - معرض الصور المصنف حسب الأصناف الخمسة مع ميزة التكبير (Lightbox).
   - سجل التعديلات والتدقيق.
   - زر **طباعة** وزر **تصدير PDF** بنمط ورقي رسمي يحمل شعار الجمهورية التونسية، بيانات البلدية، وجداول التوقيعات والأختام الرسمية.
9. **تعديل محضر المخالفة (`/violations/:id/edit`)**:
   - محمي لرتبتي رئيس الفرقة ورئيس المركز فقط.
   - حقل إلزامي لـ **"سبب التعديل"** لا يمكن الحفظ بدونه، مع تدوين غير قابل للحذف في سجل التعديلات.
10. **لوحة التقارير والإحصائيات (`/reports`)**:
    - مؤشرات رقمية رئيسية.
    - قائمة المتصدرين للمخالفين المتكررين.
    - رسوم بيانية وتوزيع نسبي حسب أصناف المخالفات والإجراءات المتخذة والحصيلة الشهرية.
11. **لوحة الإعدادات (`/settings`)** (خاصة برئيس المركز):
    - تعديل اسم التطبيق، البلدية، ورمز البلدية اللاتيني.
    - منتقيات ألوان مباشرة (Color Pickers) تُحقن فوراً في متغيرات CSS لتغيير هوية التطبيق بالكامل مباشرة.
    - إدارة الأعوان (إضافة، تعديل رتب، شارات مهنية، وحذف).
    - إدارة أصناف المخالفات وقائمة الإجراءات القانونية.
    - إدارة البيانات: تصدير نسخة احتياطية JSON، استيراد نسخة، وإعادة ضبط البيانات التجريبية.

## 🗄️ قاعدة البيانات (PostgreSQL)

يعمل المشروع على خادم PostgreSQL حقيقي تُثبّت برامجه عبر npm (الحزمة `embedded-postgres`)، لذلك لا حاجة إلى صلاحيات مدير النظام أو تثبيت PostgreSQL على الجهاز.

- **أمر التشغيل**: `npm run db` (يُنشئ العنقود تلقائياً في المجلد `.pgdata` عند أول تشغيل).
- **رابط الاتصال الافتراضي**: `postgresql://postgres:postgres@127.0.0.1:5432/police_municipale` (يُضبط في `DATABASE_URL` داخل `.env`).
- **الترميز**: UTF-8 إلزامي لدعم النصوص العربية بشكل صحيح.
- **إنشاء الجداول والبيانات الأولية**: يتم تلقائياً عند إقلاع الـ API من `server/schema.sql`، ولا تُعاد التغذية إذا كانت البيانات موجودة.
- **إعادة ضبط البيانات**: من لوحة الإعدادات، أو `POST /api/db/reset`.
- **للاستخدام مع خادم PostgreSQL خارجي** (استضافة سحابية مثلاً): غيّر `DATABASE_URL` فقط، وسيُطبّق الـ API نفس المخطط تلقائياً.

> ملاحظة: لا تُحفظ قاعدة البيانات سحابياً؛ البيانات محلية في `.pgdata` (مستثناة من git) وتُحفظ بين التشغيلات.

## 🔒 الأمان (Security)

نُفِّذت طبقة أمان كاملة على مستوى الخادم، وليس على مستوى الواجهة فقط. كل ما يلي مُختبر فعلياً على قاعدة البيانات الحقيقية.

### 1. المصادقة وكلمات المرور
- تسجيل الدخول يتم عبر `POST /api/auth/login` ويعيد **جلسة على الخادم** (Server-side session) في كوكي `HttpOnly` باسم `pm_session`؛ لا يُخزَّن أي رمز في `localStorage`.
- تُخزَّن كلمات المرور **مُجزّأة بـ bcrypt** (cost = 12) في العمود `users.password_hash` فقط. يوجد ترحيل تلقائي عند الإقلاع يحوّل أي كلمة مرور قديمة نصية إلى تجزئة ويمسح النص الأصلي.
- رمز الجلسة عشوائي (32 بايت) ويُخزَّن في القاعدة كتجزئة SHA-256 داخل جدول `sessions`، لذا لا يمكن سرقة جلسات من نسخة احتياطية.
- الكوكي: `HttpOnly` + `SameSite=Strict` + `Secure` تلقائياً عند HTTPS + انتهاء بعد 8 ساعات (`SESSION_TTL_HOURS`).
- تدوير الجلسة عند كل دخول (منع Session Fixation)، وإبطالها عند الخروج وعند تغيير كلمة المرور.
- قفل الحساب 15 دقيقة بعد 5 محاولات فاشلة (`LOGIN_MAX_FAILURES` / `LOGIN_LOCKOUT_MINUTES`)، مع مقارنة bcrypt وهمية للحسابات غير الموجودة لمنع كشف أسماء المستخدمين عبر زمن الاستجابة.

### 2. الصلاحيات (Authorization)

| الإجراء | عون | رئيس فرقة | رئيس مركز |
|---|---|---|---|
| قراءة المحاضر/المخالفين/الإعدادات/الحصائل | ✅ | ✅ | ✅ |
| إنشاء مخالف / محضر | ✅ | ✅ | ✅ |
| تعديل محضر | محاضره غير المراجَع فقط | ✅ | ✅ |
| مراجعة محضر | ❌ | ✅ | ✅ |
| إدارة الأعوان (إضافة/حذف) | ❌ | قراءة فقط | ✅ |
| تعديل الإعدادات | ❌ | ❌ | ✅ |
| إعادة ضبط البيانات / تغيير قاعدة البيانات | ❌ | ❌ | ✅ |

- هوية العون (`agentUsername`, `agentName`) وهوية المراجع (`reviewedBy`) تُؤخذ **من الجلسة** ولا يمكن تزويرها من جسم الطلب.
- حماية من حذف أو تخفيض رتبة **آخر رئيس مركز** في المنظومة.

### 3. التحقق من المدخلات ومنع XSS
- كل جسم طلب يمر عبر مخططات **Zod** (`server/validation.ts`)؛ الحقول غير المعروفة تُحذف قبل الوصول إلى القاعدة.
- تنقية النصوص من محارف التحكم و`<` و`>` (حماية إضافية من XSS المخزّن فوق تهريب React التلقائي).
- الصور: تُقبل روابط `data:image/(png|jpeg|webp|gif);base64` فقط، بحد أقصى 10 صور لكل صنف و2MB للصورة، ومنع `SVG` و`javascript:`.
- حدود حجم الطلب (12MB) ورفض أي محتوى غير `application/json` على مسارات الكتابة (‏415).
- أرقام البطاقة الوطنية (8 أرقام)، ألوان HEX، رموز البلديات، التواريخ، وإحداثيات GPS كلها مُتحقَّق منها.

### 4. منع حقن SQL
- جميع الاستعلامات **مُعاملة (parameterized)** ولا تُبنى من نص المستخدم.
- الـ API لا يعمل بصلاحيات مالك قاعدة البيانات: يُنشأ دور `police_app` عند الإقلاع بصلاحيات `SELECT/INSERT/UPDATE/DELETE` فقط، ويُمنع من `DDL` و`TRUNCATE` و`DELETE` على سجل التدقيق (تم التحقق: `CREATE TABLE` و`TRUNCATE` يُرفضان بالرمز `42501`).
- كلمة مرور الدور تُولَّد عشوائياً عند كل إقلاع ولا تُكتب على القرص.

### 5. CSRF
- توكن مزدوج: كوكي `pm_csrf` + ترويسة `X-CSRF-Token` إلزامية على كل طلب `POST/PUT/PATCH/DELETE`، مع مقارنة آمنة زمنياً.
- إضافة إلى `SameSite=Strict` وفحص `Origin`/`Sec-Fetch-Site` ورفض أي مصدر غير مسجّل في `ALLOWED_ORIGINS`.
- CORS مقيّد بأصول محددة مع `credentials: true` (وليس `*`).

### 6. تحديد معدل الطلبات (Rate Limiting)
| النطاق | الحد |
|---|---|
| كل الـ API لكل IP | 600 طلب / 15 دقيقة |
| محاولات الدخول الفاشلة لكل IP+حساب | 8 / 15 دقيقة + قفل الحساب |
| عمليات الكتابة | 150 / 15 دقيقة |
| إدارة قاعدة البيانات | 10 / ساعة |

### 7. ترويسات الأمان (Helmet)
`Content-Security-Policy` صارمة (بدون `unsafe-eval`، `object-src 'none'`، `frame-ancestors 'none'`)، `X-Frame-Options: DENY`، `X-Content-Type-Options: nosniff`، `Referrer-Policy: no-referrer`، `Cross-Origin-Opener-Policy`، وإخفاء `X-Powered-By`. HSTS يُفعّل تلقائياً عند HTTPS.

### 8. HTTPS
```bash
# 1) توليد شهادة تطوير محلية (مرة واحدة)
npm run cert:dev

# 2) تشغيل الـ API عبر HTTPS (والواجهة تتبعه تلقائياً عبر proxy)
HTTPS_ENABLED=true npm run server
npm run dev
```
- في الإنتاج: ضع `HTTPS_ENABLED=true` مع `HTTPS_KEY_PATH` و`HTTPS_CERT_PATH` لشهادة صادرة عن جهة موثوقة (أو أنهِ TLS على reverse proxy مع `TRUST_PROXY=true`).
- `HTTP_REDIRECT_PORT=3002` يضيف مستمع HTTP يعيد التوجيه 308 إلى HTTPS.
- تحذير صريح في السجل إذا عمل الخادم بـ HTTP داخل `NODE_ENV=production`.

### 9. سجل التدقيق
جدول `audit_log` (إضافة فقط، غير قابل للتعديل من الـ API) يسجّل: الدخول الناجح/الفاشل، الخروج، إنشاء/تعديل/حذف الحسابات، تعديل الإعدادات، إنشاء/تعديل/مراجعة المحاضر، ومحاولات إدارة قاعدة البيانات — مع الفاعل وIP وUser-Agent والتاريخ. لا تُسجَّل أي كلمات مرور.

### 10. متغيرات البيئة الأمنية
| المتغير | الافتراضي | الوظيفة |
|---|---|---|
| `SESSION_TTL_HOURS` | 8 | مدة الجلسة |
| `BCRYPT_ROUNDS` | 12 | قوة تجزئة كلمة المرور |
| `ALLOWED_ORIGINS` | localhost | أصول الواجهة المسموحة (قائمة بفواصل) |
| `TRUST_PROXY` | false | الثقة بترويسات الـ proxy |
| `HTTPS_ENABLED` / `HTTPS_KEY_PATH` / `HTTPS_CERT_PATH` | false | تفعيل TLS |
| `ALLOW_DB_RECONNECT` | true (تطوير) | السماح بتغيير قاعدة البيانات أثناء التشغيل |
| `ALLOW_DEMO_RESET` | true (تطوير) | السماح بإعادة ضبط البيانات التجريبية |
| `RATE_LIMIT_GLOBAL` / `RATE_LIMIT_LOGIN` / `LOGIN_MAX_FAILURES` | 600 / 8 / 5 | ضبط الحدود |

> ⚠️ **قبل النشر:** غيّر كلمات مرور الحسابات التجريبية (`agent` / `chef` / `admin`) فوراً، واضبط `NODE_ENV=production` و`ALLOWED_ORIGINS`، وفعّل HTTPS.
>
> 🔎 **ملاحظات معمارية:** عدّاد المحاولات وحدود المعدل في الذاكرة (تُصفَّر عند إعادة التشغيل وتكون لكل عملية؛ استخدم Redis عند التعدد الأفقي). صفحات البيانات في الواجهة ما تزال تعتمد التخزين المحلي (offline-first) بينما المصادقة وإدارة الحسابات تمر عبر الخادم.
